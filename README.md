# Mobile Traffic Check

Локальное веб-приложение для проверки JSON-запросов мобильного приложения в реальном времени. Оно не является расширением браузера и открывается в обычной вкладке.

## Запуск

Нужен Node.js 18 или новее:

```bash
node server.js
```

Откройте [http://127.0.0.1:8787](http://127.0.0.1:8787). На странице создайте сценарии сравнения и, при необходимости, укажите часть URL в фильтре.

## Онлайн-поток: mitmproxy, Charles и Fiddler

Все инструменты могут работать с одним веб-приложением: они отправляют записи в единый endpoint `POST http://127.0.0.1:8787/api/captures`. Добавление mitmproxy не отключает Charles или Fiddler.

### mitmproxy — готовый адаптер

Установите mitmproxy и запустите его на том же компьютере, что и веб-приложение:

```bash
pip install mitmproxy
mitmdump -s integrations/mitmproxy_to_mobile_traffic.py \
  --set mobile_traffic_endpoint=http://127.0.0.1:8787/api/captures
```

Укажите IP компьютера и порт mitmproxy (по умолчанию `8080`) в настройках Wi‑Fi телефона или эмулятора. Адаптер отправляет только запросы с `Content-Type: application/json`, не задерживает ответ приложения и исключает запросы к самому сервису, чтобы не создать цикл.

### Charles или Fiddler

Их можно продолжать использовать параллельно. Для каждого инструмента добавьте правило/скрипт, отправляющее расшифрованную JSON-запись в тот же `POST http://127.0.0.1:8787/api/captures`. На одном телефоне для одного подключения активен только один явный proxy, поэтому выбирайте proxy в настройках устройства для конкретного теста либо используйте разные устройства/эмуляторы.

Веб-страница запрашивает результаты каждую секунду и показывает совпадения со сценариями без загрузки файлов.

Пример тела запроса в локальный сервер:

```json
{
  "request": {
    "url": "https://api.example.test/events",
    "method": "POST",
    "postData": { "text": "{\"event\":\"auth_click\"}" }
  },
  "response": { "status": 200 }
}
```

Сервер доступен только на `127.0.0.1`. Он не выполняет MITM и не обходит TLS certificate pinning: Charles/Fiddler отвечает за разрешённый перехват, а приложение только принимает уже расшифрованные записи.
